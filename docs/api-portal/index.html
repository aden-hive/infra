Hive VM control plane

Each hive team owns one Firecracker microVM on the OVH e2b cluster. The VM bakes Chrome + Xvfb + the hive runtime under HIVE_HOME — it's where the team's queens and colonies execute browser-automation tools when "pinned to VM." This portal documents the control-plane API and the CLI tooling that backs it.

VM lifecycle

┌───────────────────────────────────────┐ │ account_vm.state │ └───────────────────────────────────────┘ ╳ ╳ │ │ /start (no row) │ /start (paused) │ /start (running) spawnFresh ────────────▶ running ◀──────resume──── paused ◀─────────────────────┐ │ ▲ │ /pause (user) │ │ │ /pauseForIdle (sweep) └──── pauseSandbox ────────┘ │ /reconcileToPaused │ │ /destroy (user) │ /markExternalTerminated running/paused ──── killSandbox + clearPins ────▶ terminated │ /start spawns fresh ◀─────────────┘

The desktop never calls /sandboxes/* directly. It only talks to /v1/workspace/* on hive-backend; the backend proxies through to e2b. This indirection is what lets the desktop survive e2b API drift (alias renames, endpoint reshapes) — and it's where we add cross-cutting concerns like pin persistence and event auditing.

Quick start (for teammates)

1. Get a JWT

Sign into the desktop app. In DevTools (Ctrl+Shift+I) → Application → Local Storage → look for hive_jwt (the user session JWT, distinct from the stream token). Alternatively, login via the API: 

curl -sX POST https://app-staging.open-hive.com/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"you@team","password":"..."}' | jq -r .token

2. Open the dashboard

Paste the JWT into the Dashboard and you'll see your team's VM status, recent events, and one-click buttons for start / pause / destroy and colony pin / unpin.

3. Try the API directly

The API reference embeds Scalar, which has a built-in "Try it" panel. Set Authorization: Bearer <jwt> in the request headers and fire requests against app-staging.open-hive.com.

4. Rolling templates / parity tests

Operational scripts (roll a new VM template, run parity tests between local and remote runtime, mint stream tokens) live under infra/scripts/ and infra/sandbox-images/hive-novnc/. The CLI page documents each with copy-able invocations and what it actually does.

Glossary

Workspace VM The team's single Firecracker microVM. Lives on OVH; embedded in the desktop via noVNC.
Template The OCI image + Firecracker config used to spawn fresh VMs. Currently hivev3.
Build A specific snapshot of a template, identified by UUID. roll-template.sh creates one; promotion is an alias→build pointer flip.
Alias Stable name (e.g. hivev3) that maps to a build_id. New sandboxes spawn from whatever build the alias currently points at.
Sandbox A running (or paused-and-snapshotted) instance of a build. The sandboxID appears in every embed URL.
Snapshot Six files in MinIO that capture a paused sandbox's state. Resume rehydrates from these.
Pinned colony A colony recorded in account_vm_pushed_colonies. Routing decision: chat for this colony goes to the VM, not local.
Embed token Short-TTL JWT that proves "this user is allowed to reach sandbox X's noVNC + Hive API." Signed by hive-backend, validated by client-proxy.
Stream token Per-user JWT for the Rust hive-llm proxy. Lets VM-side queens authenticate to hive-llm as the signed-in user.

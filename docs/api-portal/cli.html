CLI & scripts

Operational scripts in infra/scripts/ and infra/sandbox-images/hive-novnc/. Click any code block to copy. Scripts assume you have SSH access to the OVH orchestrator (ubuntu@135.148.52.236) and kubectl pointed at the staging cluster.

Template rollout

sandbox-images/hive-novnc/roll-template.sh

End-to-end VM template roll. Syncs the hive runtime into the image, builds a new docker tag in the OVH local registry, snapshots a Firecracker VM from it via the orchestrator's create-build binary, verifies the 6 snapshot files landed in MinIO (or local storage, depending on STORAGE_PROVIDER), then registers a new env_builds + env_build_assignments row in postgres so the alias points at the new build.

Common invocations

cd ~/aden/infra/sandbox-images/hive-novnc

# Default: bump colonies-vN, build, register against alias `hivev3`
./roll-template.sh

# Explicit alias (preferred for staged rollouts)
./roll-template.sh -a hivev3-rc

# Use a pre-existing registry tag (don't rebuild)
./roll-template.sh -t colonies-v17

# Just verify the current state — no build, no DB writes
./roll-template.sh check -a hivev3-rc

Stages it goes through

1rsync ~/aden/hive-desktop-runtime/ → orchestrator hive-src/; stamp .hive-source-rev
2docker build + push to 127.0.0.1:5000/hive-novnc:colonies-vN
3snapshot orchestrator env from /proc/<pid>/environ (so the build sees the same storage backend)
4sudo systemctl stop nomad — orchestrator releases :5007
5create-build -to-build <uuid> -template <alias> -fromImage ...
6verify all 6 files landed (memfile, memfile.header, metadata.json, rootfs.ext4, rootfs.ext4.header, snapfile)
7start nomad
8INSERT INTO env_builds + env_build_assignments
9verify via e2b API: GET https://api.vm.open-hive.com/templates
Stopping points. Snapshot verification HARD-FAILS if files are missing — alias stays pointed at the previous build. Inspect with ./roll-template.sh check -a <alias>.
sandbox-images/hive-novnc/sync-hive-src.sh

Standalone helper that mirrors the runtime tree into the template build context. Same exclusion list as hive-desktop/vendor/sync-hive.sh. Stamps .hive-source-rev and .hive-source-branch so we can correlate a baked template back to the commit. 

# Default — pulls from $HOME/aden/hive-desktop-runtime
bash sync-hive-src.sh

# Override source path
HIVE_SRC=/path/to/hive bash sync-hive-src.sh

Parity testing

sandbox-images/hive-novnc/parity-test.sh [--colony <name>]

Stages an isolated $HIVE_HOME + spawns a remote sandbox of the configured template, pushes the same multi-root colony tar to both, and compares 13 parity dimensions across the local and remote runtime (queen id, phase, LLM provider, skills list, credentials, first tool call, no auth errors, …). Used to validate a rollout before promoting an alias.

Setup

# Required env: a stream JWT (mint via scripts/mint-stream-token.sh)
export HIVE_STREAM_TOKEN=$(~/aden/infra/scripts/mint-stream-token.sh)

# Pin the candidate template alias
export HIVE_E2B_TEMPLATE=hivev3-rc

Run

# Default: bundled fixture under test-fixtures/parity_smoke
./parity-test.sh

# Explicit colony name (looks under ~/.hive/colonies/<name>)
./parity-test.sh --colony twitter_engagement_2

# Arbitrary colony path
./parity-test.sh --colony /path/to/colony

What it produces

/tmp/parity-<ts>-<pid>/report.json {overall_pass, dimensions: [{dimension, pass, local, remote, description}, …]}
/tmp/parity-<ts>-<pid>/stage/ The multi-root tar contents (colonies/ + agents/) for inspection

Acceptance gate is 13/13 PASS. The parity test ships with the rollout — see ROLLOUT-0.2.18.md in the same dir.

Tokens & auth

scripts/mint-stream-token.sh

Mints a per-user stream token JWT (HS256) — the token the hive runtime and hive-llm proxy use for user auth inside the VM. Different from the user session JWT used to call /v1/workspace/*. Reads JWT_SECRET from k8s hive-secrets via kubectl, or accepts $HIVE_JWT_SECRET as override. 

# 24h TTL, default sub/team
./scripts/mint-stream-token.sh

# Different identity + team
./scripts/mint-stream-token.sh \
  --sub teammate@adenhq.com \
  --team 14034

# Shorter TTL
./scripts/mint-stream-token.sh --ttl-hours 1

# Override secret directly (skip kubectl)
HIVE_JWT_SECRET=... ./scripts/mint-stream-token.sh

# Override namespace
./scripts/mint-stream-token.sh --namespace staging

Postgres pokes (operational)

SSH-tunneled queries

account_vm, account_vm_event, and account_vm_pushed_colonies live in hive-backend's Cloud SQL postgres. For ad-hoc reads/forensics, query directly. The e2b internal state (envs, env_aliases, env_builds) lives in a SEPARATE postgres on the OVH host — only reachable via SSH.

e2b postgres on OVH

# Resolve password from the live api process env
ssh ubuntu@135.148.52.236 '
  PASS=$(sudo cat /proc/$(pgrep -f "bin/api" | head -1)/environ 2>/dev/null \
    | tr "\0" "\n" | grep "^POSTGRES_CONNECTION_STRING=" \
    | sed "s|.*//e2b:||;s|@.*||")
  PGPASSWORD=$PASS psql -h 127.0.0.1 -U e2b -d e2b -c "
    SELECT ea.alias, eba.build_id, eba.created_at
    FROM env_aliases ea
    JOIN env_build_assignments eba ON eba.env_id = ea.env_id
    WHERE ea.alias IN ('\''hivev3'\'','\''hivev3-rc'\'')
    ORDER BY eba.created_at DESC LIMIT 6;"
'
